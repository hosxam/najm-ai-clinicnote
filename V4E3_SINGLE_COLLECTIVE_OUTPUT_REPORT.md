# V4E3 Single Collective Output Report

## Date
2026-05-19

## Summary
V4E3 removes the duplicate Step 1 output from the Advanced Encounter Builder (`?v4=encounter2`) and makes Step 6 the single collective output that includes all selected and entered content.

## Duplicate Output Root Cause

Two sources of output existed when V4 was active:

1. **Speed Mode output (`#speedOutputBox`)** — The OPD Speed Mode page (`#page-speed`) remained visible alongside the V4 Advanced Encounter Builder. Its output box, tabs, and buttons showed a full OPD note generated by `generateAllOutputs()`. This appeared near V4's Step 1 area.

2. **V4 Step 1 chip summary** — `stepWorkflow()` rendered a detailed group-by-group chip count summary (`symptoms: 3 chip(s)`, `negatives: 2 chip(s)`, etc.) that looked like an output.

Both appeared simultaneously with V4's Step 6 final output, creating a confusing dual-output experience.

## Step 1 Output Removed/Hidden

In `?v4=encounter2` only:

| What | Change |
|------|--------|
| Speed Mode output box `#speedOutputBox` | Hidden via `v4-speed-output-hidden` class |
| Speed Mode output tabs (EMR/SOAP/Follow-up/Referral/Instructions) | Hidden |

### Preserved in Step 1
- Workflow selector
- Workflow info (name, specialty, safety note)
- Simple chip badge (not an output, just a count indicator)
- Sidebar "Encounter Draft Ingredients" with all selections

## Step 6 Collective Output Behavior

Step 6 generates all 4 tabs from a single unified state object:

### Advanced EMR
- History / presenting concern
- Selected positives (chip symptoms)
- Relevant negatives (chip negatives)
- Examination (selected exam prompts + chip exam findings)
- Investigations / Results Reviewed (selected V4 options + chip investigations, deduplicated)
- Assessment (doctor-entered impression)
- Plan (chip plan phrases + Plan Assist options + doctor plan text)
- Follow-up (chip follow-up + Plan Assist follow_up + safety_netting options)

### Advanced SOAP
- SUBJECTIVE: history draft + chip symptoms + chip negatives
- OBJECTIVE: exam prompts + investigation options
- ASSESSMENT: doctor-entered impression
- PLAN: plan options + doctor plan + follow-up

### Referral Draft
- Shows full referral draft only if referral category options are selected, or "refer" appears in plan/impression text
- Otherwise shows: `Referral draft: [not requested/documented]`

### Patient Instructions
- Only plan content categorized as patient_instruction, safety_netting, follow_up, lifestyle, or counseling
- Doctor's free-text plan (cleaned of filler phrases)
- No history, exam, or investigation details
- Deduplicated against itself

### Output Rules Enforced
- Empty sections omitted (no `[not documented]` unless truly empty)
- No duplicate phrases (deduplication via normalized text comparison)
- No bracket placeholders (`removePlaceholderSentences()` strips un-filled brackets)
- No filler phrases (`cleanText()` removes "as per clinician plan", "clinician impression documented", etc.)
- No `"Denies no"` patterns (data-level check — all plan options verified clean)
- No invented diagnosis/treatment (only clinician-entered impression + selected options)
- Clinician review footer preserved in all tabs

## Known Limitations

1. **Chip refresh is manual on Step 1** — While auto-capture happens on navigation, chips changed while on Step 1 require the refresh (&#8635;) button click.
2. **Custom entries default to symptoms** — Custom chip entries are routed to the `symptoms` group regardless of context (e.g., a custom exam finding appears under symptoms in output).
3. **Placeholder name mismatches** — 3 history draft placeholder names (`[Red flag symptoms reviewed]`, `[Associated symptoms]`, `[Relevant lab results reviewed]`) don't match the draft text exactly. These are data issues, not code issues.
4. **No referral input fields** — Referral Draft depends on Plan Assist options with `referral` category or "refer" text in plan/impression. No dedicated referral reason/specialty inputs exist in V4.
